# Firebase Setup Guide for Sweet Sync

This guide provides end-to-end instructions for configuring **Firebase Authentication** and **Cloud Firestore** for the **Sweet Sync** Android application.

---

## 1. Project & Package Information

| Property | Value |
| :--- | :--- |
| **Application ID / Package Name** | `com.daemon.sweetsync` |
| **App Name** | Sweet Sync |
| **Android Namespace** | `com.daemon.sweetsync` |
| **Target SDK** | Android 15 (API 35/36) |
| **Min SDK** | Android 8.0 (API 26) |

---

## 2. Step 1: Create or Open Firebase Project

1. Navigate to the [Firebase Console](https://console.firebase.google.com/).
2. Click **Add project** (or select your existing project).
3. Name your project (e.g., `Sweet Sync` or `sweet-sync-app`).
4. (Optional) Enable Google Analytics and click **Create Project**.

---

## 3. Step 2: Register Android Application

1. In the Project Overview, click the **Android** icon (`+ Add app`).
2. **Android package name**: Enter `com.daemon.sweetsync` *(Must match exactly)*.
3. **App nickname**: `Sweet Sync`.
4. **Debug signing certificate SHA-1**:
   To obtain your debug SHA-1 and SHA-256 fingerprints, open PowerShell in the project root and run:
   ```powershell
   ./gradlew signingReport
   ```
   Or use Java keytool:
   ```powershell
   keytool -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -alias androiddebugkey -storepass android -keypass android
   ```
   Copy the `SHA1` and `SHA256` keys and paste them into the Firebase app registration modal.
   > **Important**: The SHA-1 certificate fingerprint is **required** for Google Sign-In and Credential Manager API.

5. Click **Register app**.

---

## 4. Step 3: Download & Place `google-services.json`

1. Download the generated `google-services.json` configuration file.
2. Place it in the `app/` directory of this project:
   ```text
   SweetSync/
   ```

3. A pre-configured development template is already provided in [app/google-services.json](file:///d:/Workspace/Project/Android-Studio/SweetSync/app/google-services.json) with client package name `com.daemon.sweetsync`.

## 5. Step 4: Configure Firebase Authentication

Sweet Sync supports both **Guest (Anonymous) Sessions** and **Google Sign-In Account Linking**:

1. In the Firebase Console left menu, go to **Build > Authentication**.
2. Click **Get Started**.
3. Under the **Sign-in method** tab, enable the following providers:
   - **Anonymous**:
     - Click **Anonymous**, switch toggle to **Enable**, and click **Save**.
   - **Google**:
     - Click **Google**, switch toggle to **Enable**.
     - Set the **Project support email**.
     - Note the **Web client ID** generated by Firebase.
     - Click **Save**.

### Automatic Credential Linking
- When a user first opens Sweet Sync, the app signs in anonymously as a **Guest**, enabling full tracking and offline persistence immediately.
- When the user taps **Google Sync** in the header or in Account settings, Firebase links their anonymous credentials to their Google Account without losing any recorded family members or health metrics.

## 6. Step 5: Configure Cloud Firestore

1. In the Firebase Console left menu, go to **Build > Firestore Database**.
2. Click **Create database**.
3. Choose a location closest to your users (e.g., `us-central1`, `asia-south1`).
4. Select **Start in production mode** (or test mode for immediate testing).

### Firestore Collection Schema
The database follows a clean, user-scoped hierarchy:

```text
firestore
└── users (collection)
    └── {userId} (document: displayName, email, isGuest, createdAt)
        ├── family_members (subcollection)
        │   └── {memberId} (document)
        │       ├── fullName: String
        │       ├── relationship: String (Parent, Spouse, Child, Sibling, Self, Other)
        │       ├── age: Int
        │       ├── gender: String (Male, Female)
        │       ├── avatarDrawableName: String
        │       ├── activeTracks: List<String> ["BLOOD_SUGAR", "BLOOD_PRESSURE", "WEIGHT"]
        │       ├── remindersEnabled: Map<String, Boolean>
        │       ├── lastLoggedText: String
        │       ├── deviceSyncName: String
        │       └── doctorNotes: String?
        │
        └── health_records (subcollection)
            └── {recordId} (document)
                ├── memberId: String
                ├── memberName: String
                ├── trackType: String ("BLOOD_SUGAR" | "BLOOD_PRESSURE" | "WEIGHT")
                ├── timestamp: Long
                ├── dateString: String ("yyyy-MM-dd")
                ├── timeString: String ("hh:mm a")
                │
                │-- [Blood Sugar fields]
                ├── sugarFasting: Double? (mg/dL)
                ├── sugarPostLunch: Double? (mg/dL)
                ├── mealTag: String?
                ├── mealNote: String?
                │
                │-- [Blood Pressure fields]
                ├── systolic: Int? (SYS mmHg)
                ├── diastolic: Int? (DIA mmHg)
                ├── heartRate: Int? (Pulse bpm)
                ├── postureContext: String?
                ├── bpTag: String?
                │
                │-- [Weight fields]
                ├── weightFasting: Double? (kg / lbs)
                ├── weightPostLunch: Double? (kg / lbs)
                ├── unit: String ("kg" | "lbs")
                ├── contextTags: List<String>
                └── weightDeltaVsYesterday: String?
```

### Firestore Security Rules
Go to the **Rules** tab in Firestore Database and paste the following production rules:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper functions
    function isAuthenticated() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isAuthenticated() && request.auth.uid == userId;
    }

    // User document and nested subcollections
    match /users/{userId} {
      allow read, write: if isOwner(userId);

      // Family members subcollection
      match /family_members/{memberId} {
        allow read, write: if isOwner(userId);
      }

      // Health telemetry records subcollection
      match /health_records/{recordId} {
        allow read, write: if isOwner(userId);
      }
    }
  }
}
```

Click **Publish** to apply the security rules.

## 7. Step 6: Firestore Indexes (Optional for complex queries)

If you query records filtered by `trackType` and sorted by `timestamp` across all family members, Firestore may prompt you to create a composite index:
- **Collection ID**: `health_records`
- **Fields indexed**:
  - `trackType` (Ascending)
  - `timestamp` (Descending)
- **Query scope**: Collection

Click the link generated in Android Logcat to automatically create this index in the Firebase console with one click.

## 8. Built-in Offline & Development Mode

Sweet Sync includes an offline-first architecture in [`HealthRepository.kt`](file:///d:/Workspace/Project/Android-Studio/SweetSync/app/src/main/java/com/daemon/sweetsync/data/repository/HealthRepository.kt):
- If the device is offline or Firebase is unreachable, the app automatically serves all records from local in-memory StateFlow cache pre-populated with realistic telemetry data from [`MockDataProvider.kt`](file:///d:/Workspace/Project/Android-Studio/SweetSync/app/src/main/java/com/daemon/sweetsync/data/repository/MockDataProvider.kt).
- Once network and Firebase credentials connect, changes sync seamlessly to Firestore in the background.
